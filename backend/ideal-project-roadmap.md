# Дорожная карта StoreFit

## 1. Цель проекта

StoreFit - интернет-магазин электроники для малого бизнеса с цифровым консультантом.

Проект должен показывать не просто каталог и корзину, а полноценный сценарий:

```text
каталог -> карточка товара -> корзина -> проверка совместимости -> checkout -> заказ -> склад -> уведомления
```

Главная ценность для ВКР и стартапа: покупатель получает помощь при выборе совместимых товаров, а менеджер может управлять каталогом, остатками и правилами консультанта через админку.

## 2. Техническая основа

Проект развивается как модульный монолит:

```text
backend/Store.App                 - API host, composition root, migrations, seed data
backend/Store.SharedKernel        - общие доменные building blocks
backend/Store.EventOutbox         - outbox/inbox инфраструктура
backend/Store.Identity            - пользователи, роли, авторизация
backend/Store.Catalog             - товары, категории, характеристики, цены
backend/Store.Carts               - корзина и checkout
backend/Store.Ordering            - заказы, оплата, статусы
backend/Store.Inventory           - склад, остатки, резервирование
backend/Store.Notifications       - уведомления
backend/Store.Consulting          - цифровой консультант и правила совместимости
frontend/                         - React/Vite frontend
docs/                             - диаграммы и проектная документация
```

Правила архитектуры:

1. Domain-слой не зависит от ASP.NET Core, EF Core и других модулей.
2. Application-слой работает через команды, запросы, DTO и интерфейсы.
3. API-контроллеры не принимают бизнес-решения.
4. Модули не обращаются к доменам друг друга напрямую.
5. Межмодульное взаимодействие идет через `*.Contracts`, события и outbox/inbox.
6. Frontend работает через единый API-клиент и не знает внутреннюю структуру backend.
7. Пользовательские ошибки должны быть понятными, без технических сообщений вида `Rule failed`.

## 7. Checkout, заказы и склад

После видимого консультанта нужно довести покупательский поток до надежного состояния:

1. Перед checkout проверять актуальность цен.
2. Перед checkout проверять наличие товаров.
3. Перед checkout сохранять результат проверки консультанта.
4. Резервировать товар после создания заказа.
5. Освобождать резерв при отмене.
6. Списывать товар после оплаты.
7. Показывать пользователю понятные статусы заказа.
8. Не терять пользователя при ошибке оплаты или резерва.

Критерий готовности: demo-покупка проходит от выбора товара до оплаченного заказа, а несовместимая корзина получает предупреждение до checkout.
